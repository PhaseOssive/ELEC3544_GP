# 性能优化实际验证报告

日期：2026-11-07（香港）。基于此前交付的 GP_DBLP_Author_Recovery_Standalone 源码修改，未重新开发身份算法。

## 发现与改动

用户提供的有效配置表明 XML、Profile SQLite、派生 SQLite 都直接在挂载 Drive 上工作。代码存在逐非候选姓名 SQL 查询、逐候选多次聚合查询、重复回测排名读取和缺少评分检查点等问题。本次将 SQLite/XML 工作副本移到 Colab 本地，保留用户指定的 Drive 原件与输出路径；增加本地复制/冷缓存快照、SQL 批处理、评分事务检查点、候选 CSV 校验复用和真实 I/O 进度。没有收到用户卡顿阶段日志，不能断言原七小时具体耗时分布。

## 实际测试

- 最终自动化测试：57 项通过，2.349 秒（原 45 项 + 新增 12 项）。
- 新增覆盖：新旧评分/合作证据/回测对照、评分第二次调用不重算、事务中断后保留前 25 条作者进度、精确旧签名迁移、未知输入拒绝迁移、候选 CSV 复用和损坏重导出、本地 staging/冷快照恢复、活动缓存拒绝复制、快照缺失/损坏拒绝、输入路径保护、真实子进程完整执行与自动备份、模拟 SIGINT 等待退出后备份。
- 实际旧版代码先执行小型合成 --stage scan，再由优化版 --stage all 读取同一数据库：迁移成功，日志明确复用 primary XML 扫描，最终 3 条作者确认。不是仅以手工构造旧签名代替全部迁移验证。
- rules/features/history/focal/alignment/evidence/name_repair/dedup/bootstrap 与上版逐字节一致。修改 search 的候选 Alias 查询方式；network 优化 SQL 和断点；workflow 增加阶段记录；database 增加兼容迁移与 CSV 校验。严格时间、Focal、身份阈值及四特征定义未改变。

## 30,000 篇合成端到端

空 Profile Cache 首次构建。30,000 篇、60,000 条作者出现记录、60,000 个 Profile、60,000 条出版记录，共解析 120,000 个 XML 记录。完整工作流 146.741 秒，峰值 RSS 1,051.60 MiB。60,000 条作者确认，0 未解决；四特征各 30,000 个有效值；时间越界、Focal 历史泄漏、合作网络 Focal 泄漏均为 0。原始输入前后哈希一致。

这是本地磁盘、唯一姓名的合成测试；没有 Drive 挂载的实际性能测量，没有用户的完整真实 XML，不能据此推导真实 DBLP 耗时或身份准确率。此前 176.678 秒是另一轮历史验证，不作为严格受控加速比。

在同一合成 SQLite 上依次运行旧版评分、优化评分和优化恢复。5,002 条 score 行（含两名锚作者）逐值一致。

该候选压力案例刻意包含大量没有合作证据的候选，candidate_coauthors 为 0；非空合作证据另由小型新旧对照测试覆盖。表中耗时很短，受系统缓存影响，主要证据是 SQL 数量和结果一致，不代表整个项目加速比例。两版完整 5,000 候选流程均约 1.1 秒，未观察到值得外推的总耗时差异。

## 兼容和限制

精确匹配此前 Standalone 的 recovery 代码哈希、输入/快照/语义参数后，迁移本地工作副本并保留候选/XML/去重检查点。旧版评分没有 checkpoint，升级首次会重算评分；后续按每 25 条作者的已提交边界恢复。未知签名停止，不自动清空数据库。

没有降低同步级别、删减候选、取消第二遍必要扫描或减少哈希安全检查。gzip 中断仍须顺序回放到检查点；未完成去重仍重做。除候选 CSV 外的报告目前仍重新导出。每次持久快照是完整冷缓存复制，需额外存储和时间；有进度提示。正常中断可等待退出后备份，强制回收 VM 不能保证保存尚未备份的本地进度。

本次交付不包含新的真实 599 篇恢复结果，也不承诺七小时降为一小时。应在用户 Colab 用日志和阶段计数评估实际改善。
